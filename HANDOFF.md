## 2. Ключевые игровые правила (начиная с v14)
- Основной режим — **полное завоевание 100% захватываемой суши**. 70%-ный порог отменён.
- **Нет таймера** и победы по истечении времени.
- Карта — **один связный материк**, чтобы любая земля была достижима сухопутно.
- **Порты, флот и морские высадки убраны**. Осталось **семь зданий**: ферма, лесопилка, каменоломня, шахта, казармы, крепость, город; **три исследования**: экономика, военное дело, логистика.
- Онлайн-комната создаётся **без ботов по умолчанию**; одиночный матч может запускаться с ботами.
- Мультиплеер работает через **PeerJS**, ведущий держит авторитетное состояние в своей вкладке; отсутствие автоматической миграции ведущего остаётся техническим ограничением.
- Текущее поведение/реализацию ВСЕГДА сверяй с `engine.js` и встроенным движком в `index.html`. Не полагайся на этот список как на неизменяемый код.

## 4. Непосредственный UX-контекст и болезненные точки
Последний пользовательский скриншот лобби (из v15):
- На светлой карточке белый/бледно-зелёный текст **нечитабелен**: код комнаты, параметры матча, «Покинуть комнату», вторичная информация и статусы.
- Большая коробка с вложенными коробками, дублирующий длинный текст правил, непрозрачная иерархия, слабая видимость игроков и готовности.
- Кнопки «Код»/«Ссылка» непонятны без подписи «Скопировать код» / «Поделиться ссылкой».
- Уведомления **закрывают важные данные и карту**; всплывающие окна странно накладываются друг на друга.
- Не нужно хвалиться заменой иконок на упрощённые SVG: пользователь считает их слабыми и требует **профессиональные игровые ассеты**.
- Во время зума карта не должна оказаться «под HUD» недоступной к приказам у краёв. Управление камерой должно позволять подвинуть крайние клетки к центру.
- Быстрое строительство должно быть **прямо на карте** без глубокого меню: 7 зданий, подсветка разрешённых/запрещённых клеток и нехватки ресурсов, радиус крепости до размещения, режим нескольких построек, простая отмена.
- Во время игры всегда видно важное: войска (с приростом и лимитом), **4 ресурса** (запасы/доход), территория, активные фронты, атаки соперников, соединение при проблеме; особенно опасны атаки **до** потери территории и **несколько одновременных атак**.
- Пользователь хочет, чтобы проверялись **все состояния UX, а не только статичный скрин**: открытие/закрытие, перекрытие, свайпы и масштабирование, быстрая повторная операция, ошибки, пустые/недоступные состояния, сетевое ожидание, победа/поражение, маленькие экраны и landscape. Для каждого элемента задавать уточняющие диагностические вопросы до выявления первопричины, но **не вызывать пользователя на длинный опрос** — инспектировать код и сценарии самостоятельно.

1. **Подтвердить качество v17** на реальном сайте/iPhone, прежде всего лобби: текстовые контрасты, статусы участников, copy/invite, start/leave; логика exclusive overlays без регрессии. Пользователь ещё не подтвердил, что v17 стала удобной.

3. **Полная система слоёв:** нельзя, чтобы тосты, тревога, миникарта, каталог и модальные окна перекрывали необходимые касания или конкурировали по z-index. Один главный modal/sheet одновременно, понятный закрыть/назад, safe-area для Safari, сохранение выбора после закрытия.
4. **Угрозы:** в v17 есть список атак по близости к столице и переход к каждой; точность приоритетов угроз с учётом обороны ещё не реализована.

6. **Надёжность мультиплеера:** host migration отсутствует; реальная сеть между двумя физическими iPhone/Safari не подтверждена.
7. **Технический долг:** внешний `styles/legacy.css` всё ещё большой (~149 КБ) и содержит старые слои/дубли. Не добавлять туда новые стили; удалять исторические правила постепенно, проверяя все состояния. JS-копии в HTML устранены v22.
8. **Реванш с братьями:** начать новую совместную партию без громоздкого пересоздания комнаты — пока требует улучшений.

## 6. Метод работы для нового чата
1. Через подключённый GitHub прочитай `AGENTS.md`, `HANDOFF.md`, `README.md`, `index.html`, `game.js`, `engine.js` и профильные аудит-документы. Проверяй актуальную `main`; этот handoff может устареть.

3. Выявляй причину на уровне **взаимодействия и слоёв**, не только цвета/размеров. Не плодить старые CSS-переопределения бесконтрольно; по возможности сделать согласованную систему компонентов/состояний.
